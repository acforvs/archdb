# Contributing

Every value in archdb has to be traceable to a public primary source by someone who has never seen the
repository. A pull request is accepted when `uv run archdb check-sources <model>` reports no problems and
no unchecked facts for the models it touches.

## Record format

One YAML file per model in `data/models/`. The file name is the model id.

```yaml
name: DeepSeek-V3-Base
org: DeepSeek         # must be listed in data/orgs.yaml
kind: base            # base | instruct | reasoning: the checkpoint the record describes
weights: open         # open (default) | closed: weights not public, record built from the report

sources:
  config: {url: https://huggingface.co/<repo>/resolve/<commit>/config.json, kind: config}
  report: {url: https://arxiv.org/pdf/2412.19437v2, kind: paper}
  announcement: {url: https://api-docs.deepseek.com/news/news1226, kind: blog}

not_disclosed: []                      # required fields the publisher's sources do not state

config_unused:                        # config keys that are deliberately not recorded
  num_key_value_heads: "not read by DeepseekV3Attention (MLA)"

facts:
  meta.released:
    value: "2024-12-26"
    source: announcement
    at: "DeepSeek API Docs news, Introducing DeepSeek-V3"
    quote: "Introducing DeepSeek-V3 2024/12/26"
  shape.layers: {value: 61, source: config, at: /num_hidden_layers}
  train.lr_peak:
    value: 2.2e-4
    source: report
    at: "p.22 §4.2"
    quote: "we first linearly increase it from 0 to 2.2 × 10−4 during the first 2K steps."
```

Fields are defined in [`data/fields.yaml`](data/fields.yaml). Use only registered keys; adding a field
means adding it there with a definition precise enough that two people would extract the same value.

## Completeness

An empty cell must never mean "nobody looked". Two checks enforce this:

- **Required fields.** Fields marked `required:` in `fields.yaml` must be stated or listed under
  `not_disclosed`. The condition says when a field applies: `always`, `moe` (the record has
  `moe.experts`), `swa`, `mla`, `mtp` (`mtp.depth` > 0), `dsa`, and so on; see `CONDITIONS` in
  `archdb/data.py`. Listing a field in `not_disclosed` is a claim that every primary source for the
  model (config, code, card, blog, report including appendices) was read and none states it.
  Sliding-window fields (`attn.local_*`) are stated even when they equal the global value.
- **Config coverage.** `check-sources` lists every key with a non-empty value in a cited `config.json`
  that no fact of the record mentions (in `at`, `note` or `quote`). Record it, mention it in the note
  of the fact it qualifies, or list it under `config_unused` with a specific reason ("not read by
  modeling_x.py", "serving flag"). Keys that never describe the architecture (token ids, dtypes,
  vision towers) are ignored globally in [`data/config_keys.yaml`](data/config_keys.yaml).

## Organizations and evaluations

- [`data/orgs.yaml`](data/orgs.yaml) gives each organization's country with a quote. A lab inside a
  larger company takes the parent's country.
- [`data/param_counts.yaml`](data/param_counts.yaml) is generated by `uv run archdb count-params <id>`
  from the checkpoint the record's config points to. Run it for a new record; if its count does not
  reproduce the publisher's numbers, the site shows the reason instead of a value, which usually means
  a tensor naming scheme that `archdb/checkpoint.py` does not classify yet.
- [`data/evals.yaml`](data/evals.yaml) holds independent benchmark scores (Artificial Analysis
  Intelligence Index, DeepSWE) keyed by model id, in the same fact format. Scores are
  of post-trained checkpoints; a base-model record may carry its post-trained sibling's score with a
  note naming it. Pin leaderboard pages with dated Wayback snapshots.

## Evidence rules

- **Sources are pinned.** Hugging Face and GitHub URLs use `/resolve/<commit>/` or `/<commit>/`, never
  `main`. arXiv URLs include the version (`v2`). Web pages that change use a Wayback snapshot. `kind`
  is one of `config`, `code`, `paper`, `model-card`, `blog`, `api` (Hugging Face API JSON, e.g. a
  repository creation date), `leaderboard`.
- **Every fact is mechanically checkable**, in one of two ways:
  - `at` is a JSON Pointer into a `config` source and the stored value equals what it points to.
    `/a + /b` sums two entries; `/layer_types | count full_attention` counts occurrences, `/layer_types | len` gives a length, `/weight_map | has mtp.` tests whether any key contains a substring (use it on a safetensors index to show weights are absent), and a final `a:b` segment slices a list (`/layer_types/0:92 | count sliding_attention`).
  - `quote` is a verbatim excerpt of the cited source (paper, card, code or config text) that states
    the value. Matching ignores whitespace, line-break hyphenation and Markdown/HTML markup, nothing else.
    Keep quotes short: the sentence that contains the number.
- `at` is always a human locator as well: page and section for papers, heading for cards, file and
  function for code.
- `basis: inferred` marks a value the curator derived rather than read, for example a schedule shape
  implied by an ablation. It requires a `note` that says how, and it still needs a quote or pointer for
  the input it was derived from.
- **Do not fill gaps.** If a paper does not state the warmup length, there is no `train.warmup` fact.
  Config defaults, checkpoint dtypes and serving flags are not evidence of how the model was pretrained.
- Describe the base model's pretraining. When only a post-trained checkpoint is public, say so in the
  top-level `note`.
- Numbers keep the publisher's precision. If the paper says 1.04T, store `1_040_000_000_000`, not 1T.
  Bounds the source states as bounds ("more than 30T") are stored as strings: `">30T"`.

## Common misreadings

Every one of these has produced a wrong value in an earlier version of this data.

- `head_dim` in MLA-style configs is often the RoPE sub-dimension or unused. The QK head dim is
  `qk_nope_head_dim + qk_rope_head_dim`.
- `rope_theta` on a NoPE model, or on layers that use a different base (`compress_rope_theta`,
  per-layer-type `rope_parameters`), is not the RoPE base of the global layers.
- Layers named `full_attention` can run sparse attention (DSA, MSA, QSA). Check the sparse config and
  the code.
- A config key the modeling code never reads is not evidence (`partial_rotary_factor` overridden in
  code, clamp lists, `enable_lm_head_fp32`).
- MTP declared in a config is not proof the weights were released: check the safetensors index. A
  separately trained draft model (DFlash, EAGLE, DSpark) is not an MTP head.
- Checkpoint dtype and quantization config describe the release, not pretraining precision.
- `initializer_range` and `router_aux_loss_coef` in a config are loader defaults unless the paper states
  them.
- Parameter counts differ by scope: with or without embeddings, MTP modules, vision encoders, n-gram
  tables. Record the scope in `params.note`.
- `sliding_window: 0` or `null` means no sliding window, not a window of 0.
- KV caches that are compressed or shared across layers (DeepSeek-V4 CSA/HCA, cross-layer reuse,
  index caches owned by a subset of layers) are described with `attn.kv_groups`; the standard
  `kv_heads × (head_dim + v_head_dim)` formula would be wrong for them.
- Paper numbers from ablations, proxy models or sibling sizes do not describe the released model.

## Vocabulary

Free-text fields use consistent spellings so columns sort and compare:
`ffn.activation` SwiGLU, GeGLU, ReLU², SiTU-GLU, GELU; `norm.type` RMSNorm, RMSNorm (1+w gain),
LayerNorm, LayerNorm (no bias); `norm.placement` pre, post, sandwich, parallel; `moe.router` softmax,
sigmoid, normalized sigmoid, hash; `attn.kind` from GQA, MQA, MHA, MLA, SWA, DSA, CSA, HCA, MSA, QSA,
Gated DeltaNet, KDA, Lightning, Mamba-2. Specifics go in parentheses after the canonical term.

Numbers in free text: counts and sequence lengths with thousands separators (`15,360 × 4,096`),
token amounts in decimal units at the publisher's precision or three significant figures (`62.9M
tokens`, `14.8T`). `K` for context lengths is binary (`32K` = 32,768), as configs use it.

## Checks

```sh
uv run archdb validate                 # schema, types, citations, required fields
uv run archdb check-sources            # fetches sources into .cache/, verifies pointers, quotes, config coverage
uv run archdb check-sources kimi-k2    # one model
uv run pytest
```

`check-sources` needs `pdftotext` (poppler) for PDF sources.
